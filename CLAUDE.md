Этот файл читается в начале каждой новой сессии. Здесь: как работать с заказчиком, где что лежит,
что уже сделано и что дальше. Обновляйте его в конце каждой рабочей сессии.

## Как работать с заказчиком (обязательно)

- Говорить по-русски. Заказчик — Моше, не разработчик, но точно выполняет пошаговые инструкции.
- Всё, что требует его действий (регистрации, ключи, настройки), — по одному шагу, коротко, с названиями кнопок.
  Интерфейсы сервисов меняются: если кнопки нет, просить снимок экрана, а не гадать дальше.
- **Никогда не просить присылать в чат пароли, секретные ключи и токены.** Секреты кладёт он сам:
  в Vercel (Settings → Environments → Production → Environment Variables) или в `.env.local`.
- Перед любой платной операцией: что именно, сколько стоит (сверить на официальной странице) — и ждать «да».
- Работать по этапам из раздела 13 ТЗ. После этапа — рабочая версия на Vercel и список, что проверить.
- Проверять свою работу (сборка, страницы в браузере, данные в базе), а не считать задачу готовой по факту написания кода.
- Если в ТЗ чего-то не хватает или есть противоречие — сказать до начала работы, не додумывать молча.
- Любое изменение требований вносить в ТЗ.

## Переменные окружения

Открытые значения (адрес Supabase, publishable key, имя бота) зашиты в `src/lib/env.ts` как значения по умолчанию:
Vercel не дал заказчику сохранить имена с `NEXT_PUBLIC_`. Переменные `NEXT_PUBLIC_*` их переопределяют, если появятся.

Секреты (в Vercel, окружение Production):
- `SUPABASE_SECRET_KEY` — секретный ключ Supabase `sb_secret_…` (не publishable! код это проверяет).
- `TELEGRAM_BOT_TOKEN` — токен бота от @BotFather. Из него же выводится секрет вебхука (`webhookSecret`), отдельной переменной нет.
- `CRON_SECRET` — необязательно; если задан, `/api/cron/daily` принимает только вызовы Vercel Cron.

Полный список с пояснениями — `.env.example`.

## Архитектура и подводные камни

- **Next.js 16.4** (новее данных обучения модели). Перед кодом читать `node_modules/next/dist/docs/` (см. `AGENTS.md`).
  `middleware` теперь `proxy` (`src/proxy.ts`). `params`/`searchParams` — Promise.
- `cacheComponents: true`: чтение cookie/searchParams только внутри `<Suspense>`; данные кэшируются через `'use cache'`
  с тегами (`dictionaries`). `partialPrefetching: false` — чтобы неизвестная карточка отдавала честный 404 (SEO).
  `generateStaticParams` обязан вернуть хотя бы один элемент.
- Публичные страницы статичны: состояние входа в шапке читается в браузере (`UserMenu`), proxy работает только на
  `/profil`, `/kabinet`, `/admin`, `/vhod`, `/auth`, `/api`.
- Адреса: `/<раздел>/<slug>` — категория **или** карточка; база не даёт им совпасть (триггер `check_slug_namespace`).
  Второй уровень — подкатегория или район. Старые адреса карточек — `listing_slug_history` (для 301).
- Карточка = `listings` + версии `listing_versions` (данные блоков в JSON). Типы блоков — `src/lib/blocks/types.ts`.
  Публикация — SQL `publish_listing_version(version)`: переносит данные в поисковые поля `listings` (`refresh_listing_search`).
  **`listings.features` (jsonb) — включённые платные функции; особенности заведения — `listings.amenities` (text[]).**
  Поиск — SQL `search_listings(...)`; псевдонимы районов/категорий — колонки `aliases`, синонимы — `search_synonyms`.
  Категория из адреса (`p_category`) фильтрует строго (с подкатегориями); слово категории во фразе только поднимает
  её карточки выше (их и так находит текст: название и псевдонимы категории попадают в `search_tsv`).
  **После правки псевдонимов категорий нужно вызвать `refresh_listing_search` для карточек этих категорий.**
  Подкатегория: `categories.parent_id`, адрес `/<раздел>/<категория>/<подкатегория>`; `/<раздел>/<подкатегория>` → 301.
  Данные каталога кэшируются с тегом `listings`: после публикации/правки нужно сбрасывать (`revalidateTag`).
- Вход через Telegram (`src/lib/auth/telegram-session.ts`): подпись проверяется на сервере, пользователь Supabase
  создаётся со служебным адресом `tg-<id>@telegram.invalid`, сессия — через `generateLink` + `verifyOtp`.
  Supabase записывает `app_metadata` **после** вставки пользователя — поэтому есть триггер на обновление и явная запись в коде.
- Привязка: одноразовые токены `link_tokens` (10 минут). «Открыть в Telegram» → `t.me/haifabcbot?startapp=link_<token>`.
  «Привязать Google» → cookie + вход Google → `merge_profiles`.
- **`merge_profiles` (SQL) нужно дополнять** каждой новой таблицей со ссылкой на пользователя (избранное, отзывы, заявки).
- Карта: `src/components/catalog/catalog-map.tsx` (каталог, `?view=map`, до 100 меток) и `place-map.tsx` (блок «Адрес»).
  Координаты — SQL `listing_points(ids)`. **MapLibre 6 грузит воркер отдельным файлом**: `scripts/copy-maplibre-worker.mjs`
  копирует его в `public/maplibre/` (postinstall и prebuild), адрес задаётся через `setWorkerUrl`. При обновлении
  maplibre-gl ничего делать не нужно, файл копируется заново.
- **Блоки карточки:** тип — в `src/lib/blocks/types.ts`, отображение — в `listing-view.tsx` (+ `components/listing/blocks/`),
  поиск по тексту блока — в SQL `refresh_listing_search`. Новый тип блока = все три места.
- **Устаревшее скрывается при загрузке карточки** (`pruneExpired` в `src/lib/blocks/expire.ts`, внутри кэша на час):
  спецпредложения после `validUntil`, мероприятия после даты, вакансии после `validUntil` (по умолчанию 30 дней от
  `postedAt`), прошедшие особые дни. В поиске «есть спецпредложение» проверяет `offer_until` в момент запроса.
  Даты и время мероприятий хранятся как местное время Израиля без пояса (`2026-11-20T18:00`).
- `listings.hours` = неделя + ключ `exceptions` (особые дни); `is_open_at` и `OpenNowBadge` сначала смотрят исключения.
- **Короткая ссылка:** `listings.short_code` (6 знаков, генерируется базой), маршрут `src/app/k/[code]/route.ts` → 301.
  QR-код (пакет `qrcode`) рисуется на сервере в странице карточки и ведёт на короткую ссылку. Пока адрес *.vercel.app
  временный, QR не печатать — после подключения домена сменится только домен, коды останутся.
- **Mini App открывает карточку** по `t.me/haifabcbot?startapp=b_<slug>` (бизнес) или `s_<slug>` (специалист):
  `mini-app-bridge.tsx` читает `start_param` и переходит на карточку один раз за сессию. В Telegram ещё не проверено.
- **Видео:** обложка YouTube с `i.ytimg.com`, плеер `youtube-nocookie.com` грузится только по нажатию. Скриншоты
  встроенного браузера показывают играющее видео чёрным — проверять через postMessage-событие `onReady`.
  Обложки Vimeo берутся через oEmbed на сервере (`src/lib/data/video.ts`).
- Отметки меню: `veg` 🌱, `spicy` 🌶️. Разметка: `hasMenu` (Menu) и отдельные `Event` для мероприятий; для вакансий
  JobPosting не ставим (Google разрешает только на отдельной странице вакансии).
- **Этап 3, модерация (`src/lib/blocks/moderation.ts`):** `MODERATED_TYPES` — блоки, которые ждут проверки (плюс шапка
  и контакты); остальное, порядок, скрыть/удалить блок — публикуется сразу. Отправка (`submitListing` в
  `src/app/actions/cabinet.ts`): `diffListing` делит правки, мгновенные собираются `applyChanges` в новую версию и
  публикуются (`publish_listing_version` секретным клиентом), пишутся в `instant_changes`; остальные — версия `pending`
  с `moderated_keys` (`["*"]` — новая карточка целиком). Админ одобряет часть ключей (`decideVersion`), «Снять» —
  `revertChange`. Администратор в редакторе публикует сразу всё. Тест логики был разовым скриптом (в репозитории нет).
- **Редактор** строится по схемам `src/lib/editor/schemas.ts` (поля `src/components/editor/fields.tsx`); на сервере
  данные чистит `sanitizeListingData` (`src/lib/blocks/sanitize.ts`): неизвестное отбрасывается, фото — только из
  bucket `media` (или Unsplash у примеров), ссылки — только http(s). Новый блок = types.ts + схема + listing-view.tsx +
  sanitize.ts + (если нужен поиск) `refresh_listing_search`.
- **Фото:** сжимаются в браузере до 2000 px WebP (`src/components/editor/upload.ts`), пишутся в `media/u/<id пользователя>/`
  (правила storage пускают только в свою папку); импорт кладёт в `media/import/` через sharp.
- **Записи в новые таблицы (отзывы, жалобы, заявки) — только с сервера** секретным клиентом после `requireUser`/капчи/
  `rateLimit` (`src/lib/server/*`): insert-политик для anon/authenticated нет намеренно. Публичные отзывы читаются
  функцией `listing_reviews` (без id пользователя). Статистика — `track_listing_event` из браузера (`listing-tracker.tsx`).
- Серверные действия: `src/app/actions/{public,cabinet,admin,import}.ts`, результат `ActionResult` через `runAction`.
  После изменений публичных данных — `updateTag("listings")` (справочники — `dictionaries`, настройки — `settings`).
- Telegram: `notifyAdmins`/`notifyUser` (`src/lib/telegram/notify.ts`) шлют через Bot API в `after()`; учитывают
  `profiles.notify_prefs`. В очереди PostgREST связь listing_versions→listings указывать явно:
  `listings!listing_versions_listing_id_fkey(...)` (есть вторая связь через published_version_id).
- **Этап 4, Telegram (`src/lib/telegram/`):** все вызовы Bot API — через `safeCall` (ошибки не ломают действие;
  403 → `telegram_chats.blocked_at`). Кто нажал «Старт» — таблица `telegram_chats` (пишет middleware бота на любое
  сообщение в личке). Настройки канала — `bot_settings` (ключи `channel`, `channel_candidate`), не публичные.
  Вебхук: `webhookCallback(bot, "std/http", { secretToken })`, бот кэшируется на экземпляр функции.
  **Новый путь публикации карточки должен вызывать `onFirstPublish` / `onOffersPublished`** (`channel.ts`); импорт
  намеренно не вызывает. Ключ спецпредложения — `<id блока>:<название>`; связь с `instant_changes` нужна для «Снять».
  Статус заявки менять только через `decideRequest` (`requests.ts`): он правит сообщение владельцу и пишет клиенту.
  Заметка владельца (`owner_note`) клиенту не уходит. Фото для постов перекодируются sharp в JPEG (свои фото — WebP).
  Пункт дайджеста не удаляется (одно сообщение на много пунктов). `/api/cron/daily` — с `await connection()`,
  иначе при `cacheComponents` GET-обработчик пытается собраться при сборке.
- **proxy** работает на `/api/auth/*`, но не на вебхуке и cron. Кнопка «Назад» Telegram (`usePathname`) в layout — внутри
  `<Suspense>`, иначе сборка падает. Кнопки Mini App ждут события `hbc-telegram-ready` от `MiniAppBridge`.
- Проверка бота без Telegram: разовый скрипт с `bot.api.config.use(...)` вместо сети и `bot.botInfo` вручную,
  `npx tsx --conditions=react-server`; справочники (`'use cache'`) подменить через paths в отдельном tsconfig.
- Карта Google в блоке «Рейтинг на Google»: на узкой карте Google не показывает карточку с рейтингом (видна только на
  широкой, ~640 px), поэтому под картой всегда кнопка «Читать отзывы в Google Картах». С ключом Embed API — проверить заново.
- Шрифты: текст — Onest (`@fontsource-variable/onest`, `--font-sans`), заголовки h1–h3 — Manrope
  (`@fontsource-variable/manrope`, `--font-display`, класс `font-display` для прочих крупных надписей); оба с нашего домена.
  Палитра — под логотип: основной `#1e1b4b`, наведение `#312e81`, мягкий `#ecebfa`, фон `#f6f6fb`, акцент прежний
  `#c2410c`. Цвет прописан ещё в метках карт (`place-map.tsx`, `catalog-map.tsx`), `themeColor` в layout и фоне Mini App.
  Фото примеров — Unsplash через `src/components/ui/photo.tsx`.
- Правила оформления: фото, иконки и эмодзи; **никакой горизонтальной прокрутки** — меню и чипы переносятся (`flex-wrap`).
  **Проверка переносов:** разовый скрипт Playwright на 320/360/375/390/412 px считает строки надписи через
  `Range.getClientRects()` у кнопок, чипов и бейджей (кнопки-картинки «🔍»/«▶» — ложные срабатывания).
  Короткие бейджи (`rounded-full` + `text-xs`) — с `whitespace-nowrap`. Не использовать `pkill -f`/`pgrep -f` с
  шаблоном, который есть в самой команде: убивает собственную оболочку (`pgrep -f "[n]ext-server"`).
  Только простые эмодзи без склеек (не 🧑‍🔧, 👩‍⚕️): на Windows составные распадаются на два значка.

## Проверка в песочнице без интернета

Песочница может не видеть Supabase, Vercel и Google Fonts. Проверочная сборка с подменой базы (второй аргумент —
миграция с примерными карточками, тогда собираются и их страницы, а `/k/demo1`…`/k/demo5` ведут на них):

```bash
python3 -I scripts/supabase-stub.py supabase/migrations/20261101000002_seed_dictionaries.sql \
  supabase/migrations/20261102000007_card_blocks.sql &
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 npm run build
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321 npx next start -p 3100
```

Редактор без входа можно посмотреть локально: временная страница с `<ListingEditor>` и данными из миграции примеров
(не коммитить) + Playwright на 375/320 px. Живой сайт смотреть встроенным браузером приложения Claude. Перед `npx tsc --noEmit` выполнить `npx next typegen`.
Если окно Claude у заказчика в фоне, скриншоты встроенного браузера «застывают» — проверять вёрстку через JS
(`scrollWidth`, `getBoundingClientRect`), ширина телефона — `resize_window` 375 и 320. Фото Unsplash проверять загрузкой
`new Image()` в браузере: из песочницы images.unsplash.com недоступен.
